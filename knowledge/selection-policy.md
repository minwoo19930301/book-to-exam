# 내부 출제 KB의 선별 기준

목적은 교재의 축소 복사본이나 학습용 위키 화면이 아니다. 문제를 만들 때 무엇을 묻고, 어떤 차이를 채점할지 빠르게 판단하는 작은 Markdown 지식이다. 원문 전사는 `public/data/subjects/*/notes.json`, 평가원 자료는 `kice/pages.json`에 따로 둔다.

## 남기는 것

- 개념의 경계: 비슷한 제도·사건·이론을 가르는 조건과 적용 범위.
- 인과와 변화: 문제 상황→선택한 수단→결과·한계, 전후의 차이.
- 사료 판별: 용어·주체·시점·관점 중 답을 결정하는 단서.
- 실제 문항에서 요구하는 사고: 식별·비교·설명·순서·자료 해석·수업/평가 설계.
- 오답이 되는 이유와 출제 보류 사유. 원문이나 해설에 있다는 이유만으로 정답으로 승격하지 않는다.

`priority: core`는 위 기준에 따른 편집 판단이다. 출제 빈도·통계적 확률·전 범위 완성을 뜻하지 않는다. 기출교재의 출제 예측 문구나 검색 키워드의 겹침을 검증된 평가원 출제 근거로 쓰지 않는다. `examIds`에는 실제 면 단위 문항을 읽고 연관을 확인한 경우만 연결한다. 빈 배열은 미확인 상태이다.

## 원문 조회로 넘기는 것

중복 설명, 긴 사료 인용, 학자 약력·저서 목록, 답의 판별에 쓰이지 않는 세부 인명·연도·수치, 완전한 통사적 서술. 이들은 삭제된 사실이 아니라 필요할 때 읽는 근거 데이터다. 상세 내용 자체를 묻는 문항을 만들려면 다시 검증한다.

## 출제 순서

1. `prepare_exam`으로 주제별 근거 묶음을 받거나 `index.md`/`search_knowledge`로 짧은 문서 1~3개를 고른다. 모든 교재를 한 번에 문맥에 넣지 않는다.
2. 문서의 핵심·함정·보류와 `sourceIds`(본문의 S1, S2 순서)를 확인한다. `get_note`로 필요한 원문만 읽는다.
3. 한 문항의 판단 기준을 정한 뒤 정답 근거와 오답 이유를 작성한다. 문항의 모든 사실은 근거에 있어야 한다. 출처가 불명확하거나 충돌하면 보류한다.
4. 유물·지도·인물·도표의 식별을 요구하면 해당 노트의 실제 `figures`를 확인하고 이미지 ID를 함께 연결한다. 그림이 없거나 가려졌다면 그 그림을 전제로 출제하지 않는다. 글로 그림을 추정해 만들지 않는다.
5. 원문 인용·과목·자료 ID·정답의 유일성·선지 논리를 검증한 문항만 은행에 넣는다. 단순한 원문 문자열 일치는 역사적 정확성 검증이 아니다.

사진 영역 검수와 교재 내용 전체의 검수는 별개다. `automaticExamEligible: false`를 유지하며, KB의 짧은 요약만으로 자동 출제를 승인하지 않는다. 새 오류나 더 좋은 구별 기준을 찾으면 원문은 보존하고 해당 압축 문서를 수정한다.

## 구조와 재생성

`compact/<subject>/*.md`가 편집 원본이다. HTML 주석의 작은 JSON metadata는 ID·과목·근거 목록만 담는다. `tools/history-kb/compact.py`가 내부 MCP용 `functions/_data/knowledge.json`과 로컬 검색 색인을 생성한다. 이 JSON은 Markdown의 컴파일 결과이며 별도로 편집하지 않는다. 공개 `wiki.json`과 사용자용 위키 화면은 생성하지 않는다.

`compact-report.json`의 압축률은 Unicode 문자 수 비율이다. 모델 토큰 수·학습 성과·전 범위 검수율이 아니다.
