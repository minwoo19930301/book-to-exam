# 동양사 교재에서 실제로 깨진 지점

「선생님을 위한 동양사」(구영모) 309장 펼침 작업 기록. 마케팅이 아니라 재발 방지용.

## 역할이 바뀌어서 망가짐

초반 agy 구간(`_gen_21_60.py` 계열)은 “이 페이지를 ① ㉠로 받아라”였다. 밀도가 책과 같다.

중간에 Cursor가 끼어든 일은 원래 뷰어·표지·쪽수였다. 그 자체는 agy가 처음부터 했어도 따로 필요했다.

뒤가 얇아진 직접 원인: `_build_261_309.py` 첫 줄이 「순수 한글 임용 서브노트 생성」. OCR이 안 읽히자 복원을 포기하고 키워드 노트를 썼다. Apple Vision이 없어서가 아니다. Vision 결과는 이미 있었고, 그걸 힌트로 글자를 살리지 않았다.

agy로 다시 가도 프롬프트가 “서브노트”면 같은 요약이 나온다. 도구 교체가 아니라 **계약 유지**가 핵심이다.

## 쪽수

| 파일 | 실제 인쇄 |
|---|---|
| `part1_page_001` | 안쪽 표지 + 속표지 (1–2 아님) |
| `part1_page_002` | 4–5 차례 |
| `part1_page_012` | 22–23 |
| `part1_page_015` / `016` | 28–29 (016이 더 깨끗) |
| `part1_page_017` | 28–29 **넘김** (손). 카드로 쓰지 말 것 |
| `part1_page_021` | 36–37 |
| 일본 교육칙어 펼침 | 406–407 (뷰어가 404–405로 달린 적 있음) |

2–3쪽은 촬영되지 않았다.

## 36–45는 OCR 문제가 아님

공자가 36 왼쪽으로 가고 38–39 카드가 빠지고, 묵가가 41로 가고, 42–43 HTML이 깨지고, 44–45가 넘김 사진(`030`)을 쓰는 식. **매핑/배치**. 이 구간은 재OCR이 아니라 쓸 컷을 고르는 일이다.

## agy 병렬 운영

- 작업 디렉터리는 거대한 git(원본 프레임 수천 장) 밖. 전용 `git init`.
- 워커 7–8장, jsonl 분리, skip-existing.
- 새벽 1:22 4마리가 동시에 401. 이미 쓴 줄은 살리고 나머지만 재개.
- 10마리 wave2로 남은 73장을 나눈 뒤가 안정적.

## 뷰어

새 미리보기 HTML을 만들면 사용자는 “기존 UI 왜 안 쓰냐”고 한다. 주입은 기존 `동양사_스마트_교재뷰어.html`만. 백업 남기고 22–23 이전 카드는 유지.
